# Contributing guidelines

Thank you for your interest in contributing to the Awesome Neural Network Formal Verification list!

To maintain the high quality of this curated list, please follow these guidelines when opening a pull request:

## Guidelines

- **Quality and relevance**: The tool, framework, paper, or resource must be directly related to the formal verification of neural networks.
- **Relevance and rigor (for tools)**: To prevent cluttering, new tools should be publicly available, open source, and either associated with a peer-reviewed academic publication (e.g., CAV, POPL, ICLR, NeurIPS, IEEE S&P), evaluated in competitions (such as VNN-COMP), or actively maintained with demonstrated community adoption.
- **Maintenance**: Tools should ideally be active or maintained within the last two years. Legacy tools of significant historical importance (e.g., Reluplex) are exceptions.
- **Descriptions**: Keep descriptions objective, concise, and focused on the core technology, algorithm, or use case. End all descriptions with a period.
- **Alphabetical order**: Ensure the new entry is placed in alphabetical order in its respective category.
- **Formatting**:
  - Links should be clean and point directly to the source repository or official paper.
  - Do not use pull request descriptions for self-promotion.

## Submission process

1. Fork the repository.
2. Create a new branch for your addition.
3. Add the resource, ensuring it is alphabetically sorted and follows the description guidelines.
4. Open a pull request with a clear title and a brief description explaining why the addition is valuable.
